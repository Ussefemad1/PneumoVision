# PneumoVision on AWS EC2

One `m7i-flex.large` instance in **eu-north-1** (2 vCPU, 7.6 GiB RAM, no GPU,
30 GiB gp3, 4 GiB swap) runs the whole stack with Docker Compose: nginx (TLS),
the web app, the API, MongoDB, Redis, MinIO, and the inference service serving
the **Round 3 MedPatch fusion** models on CPU (`INFERENCE_MODE=fusion`).

- **Address.** No domain is needed. The site is at
  `https://<ip-with-dashes>.sslip.io`, with a Let's Encrypt certificate.
- **Restarts.** Every container has `restart: always`, so the stack comes back
  by itself when you start the instance.
- **No paid add-ons.** No RDS, DocumentDB, EFS, ALB, NAT gateway or CloudFront.
  Only the instance, its disk and the Elastic IP.

Every command below is for **Windows PowerShell** on your PC, unless it runs
inside `ssh … "…"`, which runs on the server.

## Data safety: read first

- **No MIMIC data on the server, ever.**
  - **Synthetic data only.** The only data on the server are the synthetic
    patients in `docs/demo-examples/` and the synthetic seed.
  - **Partial clone.** `bootstrap.sh` makes a _partial_ clone (sparse,
    `--filter=blob:none`). The MIMIC-derived files that are tracked in git are
    never downloaded, not even into `.git`: `medpatch/mimic4extract/`,
    `mimic-cxr-ehr-split.csv` and `valset*.csv`.
  - **Deploy guard.** Every `deploy.sh` runs `data-guard.sh` first. It refuses to
    continue if the checkout or `checkpoints/` holds any of these:
    - an off-limits file from CLAUDE.md;
    - any `*.csv` other than the four synthetic demo vitals files;
    - a pickle;
    - anything in `checkpoints/` that is not a `*.pth.tar` or `run.json`.
- **Demo X-rays.** Where they come from (`docs/demo-examples/README.md`, git
  log):
  - `cxr_pneumonia_lobar.jpg`: Wikimedia Commons, Mikael Häggström, CC0.
  - `cxr_pneumonia_covid_ap.jpg`: Wikimedia Commons, Hellerhoff, CC BY-SA 3.0.

  Neither is from MIMIC; both are deployed.

- **Two PNGs left out.** `sick cxr.png` and `not sick cxr.png` were added in
  commit `836a211` (2026-10-16) with **no source or licence recorded**. Their
  provenance cannot be shown, so they are **excluded** from the server. The
  sparse clone leaves them out, `.dockerignore` keeps them out of images, and
  the guard refuses them. Ask whoever added them where they come from. If it is
  MIMIC-CXR, delete them from the repo.
- **Weights.** Checkpoints are never in git or in an image. They are copied to
  the server's disk ([copy-checkpoints.md](copy-checkpoints.md)) and mounted
  read-only.
- **Discharge notes and mortality.** Discharge notes never reach the mortality
  model. The API filters them out, and the inference service refuses them with
  a 400.

## 0. Once, on your PC

Install the AWS CLI if you want the start/stop commands below. Otherwise use
the EC2 console buttons. Then set these for the PowerShell session:

```powershell
$Key = "$HOME\.ssh\pneumovision.pem"     # the key pair's .pem file
$Ip  = "203.0.113.7"                      # your Elastic IP
$Id  = "i-0123456789abcdef0"              # the instance id
$Region = "eu-north-1"
$Site = "https://$($Ip -replace '\.', '-').sslip.io"
```

If ssh complains that the key is too open, restrict it to your user:

```powershell
icacls $Key /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

## 1. Start the instance and connect

```powershell
aws ec2 start-instances --instance-ids $Id --region $Region
aws ec2 wait instance-running --instance-ids $Id --region $Region
ssh -i $Key ubuntu@$Ip
```

Type `exit` to leave the ssh session.

## 2. Bootstrap (first time only)

```powershell
ssh -i $Key ubuntu@$Ip "curl -fsSL https://raw.githubusercontent.com/Ussefemad1/PneumoVision/main/infra/aws/bootstrap.sh -o bootstrap.sh && bash bootstrap.sh"
```

- **Admin password.** The script prints the admin password **once**. Store it
  in your password manager now.
- **Rerunning is safe.** A rerun never changes a secret.
- **Email for certificate notices (optional).** Run it with
  `LETSENCRYPT_EMAIL=you@example.org bash bootstrap.sh`.

It writes `~/PneumoVision/.env` (mode 600) with every secret generated by
openssl:

- the JWT Ed25519 keypair;
- the field-encryption key;
- the CSRF and HMAC secrets;
- the Mongo, Redis and MinIO passwords;
- the admin password.

## 3. Copy the checkpoints (first time only)

Follow [copy-checkpoints.md](copy-checkpoints.md): four files, about 1.1 GiB.

## 4. Deploy

```powershell
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/deploy.sh"
```

The first run builds the images on the server, which takes about 15–25
minutes. Then it does the following:

- waits for the models to load (a few minutes on 2 vCPUs);
- gets the Let's Encrypt certificate;
- checks `https://<host>/api/v1/health` through nginx, and the inference
  service's `/v1/health` from inside the Docker network.

Any failure stops it with a message that says what to fix.

If a build runs out of memory, which is not expected with 7.6 GiB plus swap,
rerun it with:

```powershell
ssh -i $Key ubuntu@$Ip "NODE_OPTIONS=--max-old-space-size=2048 ~/PneumoVision/infra/aws/deploy.sh --no-pull"
```

## 5. Open the site and sign in

```powershell
Start-Process $Site
```

- **Signing in.** Sign in as `admin@pneumovision.local` with the password from
  step 2.
- **Accounts.** There is no public sign-up, and no account with a known
  password exists.
- **First start.** The API seeds the synthetic demo ward and scores it with
  the real models in the background. That takes a few minutes on CPU, and the
  ward fills in as it goes.

### Add a user

Run as the admin, on the server. The password is generated and printed once:

```powershell
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/compose.sh exec -T api node apps/api/dist/cli/users.js create --email dr.a@example.org --name 'Dr A' --role clinician"
```

- **Roles.** `clinician`, `radiologist`, `researcher` or `admin`.
- **Reset a password.**
  `… users.js reset-password --email dr.a@example.org`.
- **Disable an account.**
  `… users.js deactivate --email dr.a@example.org`.

## 6. Stop the instance after the demo

```powershell
aws ec2 stop-instances --instance-ids $Id --region $Region
```

Everything (database, uploads, certificates) is on the disk and comes back at
the next start. The Elastic IP stays attached, so the address does not change.

## Update after a push to `main`

```powershell
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/deploy.sh"
```

It runs `git pull --ff-only`, then the guard and the checks, rebuilds what
changed and restarts.

## Logs and status

```powershell
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/compose.sh ps"
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/compose.sh logs --tail=100 inference"
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/compose.sh logs --tail=100 api"
ssh -i $Key ubuntu@$Ip "docker stats --no-stream"
```

Container logs rotate at 10 MB × 3 per container. The inference service logs
only the request id, task, which inputs were present, and latency. It never
logs input content.

## Backup and restore

The backup writes to `~/backups` and prints the `scp` line that pulls it to
your PC:

```powershell
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/backup.sh"
scp -i $Key "ubuntu@${Ip}:~/backups/pneumovision-*" "$HOME\Downloads\"
```

To restore a database backup (this replaces the current data):

```powershell
scp -i $Key "$HOME\Downloads\pneumovision-20261017-120000Z.mongo.gz" "ubuntu@${Ip}:~/backups/"
ssh -i $Key ubuntu@$Ip "~/PneumoVision/infra/aws/backup.sh restore ~/backups/pneumovision-20261017-120000Z.mongo.gz"
```

**Take a backup and pull it to your PC before the credits run out.** On the
Free plan the account is then **closed**, not billed, and the instance and its
disk are deleted with it.

## Your home IP changed (ssh times out)

SSH (port 22) is open only to your IP. Replace the rule with your new address:

```powershell
$Sg = (aws ec2 describe-instances --instance-ids $Id --region $Region --query "Reservations[0].Instances[0].SecurityGroups[0].GroupId" --output text)
$MyIp = (Invoke-RestMethod https://checkip.amazonaws.com).Trim()
aws ec2 describe-security-groups --group-ids $Sg --region $Region --query "SecurityGroups[0].IpPermissions[?FromPort==``22``].IpRanges[].CidrIp" --output text
aws ec2 revoke-security-group-ingress --group-id $Sg --region $Region --protocol tcp --port 22 --cidr <old-ip>/32
aws ec2 authorize-security-group-ingress --group-id $Sg --region $Region --protocol tcp --port 22 --cidr "$MyIp/32"
```

Or in the console: EC2 → Security Groups → the instance's group → Edit inbound
rules → the SSH rule → Source: **My IP**.

Ports 80 and 443 stay open to everyone. Let's Encrypt needs port 80. Do not
enable `ufw`: Docker manages the published ports itself, and the security
group is the firewall.

## Credit checklist (you must never be charged)

| State   | Approx. cost                       | What it is                                                           |
| ------- | ---------------------------------- | -------------------------------------------------------------------- |
| Running | **~US$2.30 / day** (~US$0.096 / h) | m7i-flex.large on-demand + 30 GiB gp3 + public IPv4                  |
| Stopped | **~US$0.20 / day**                 | 30 GiB gp3 (~US$0.08) + the idle Elastic IP's public IPv4 (~US$0.12) |

- **Stop it after every demo.** A forgotten running instance costs about
  US$70 a month of credits.
- **Check the credit balance.** Look at Billing → Credits weekly. A Zero-spend
  or monthly AWS Budget alert (Billing → Budgets, free) emails you before the
  credits are spent.
- **Avoid paid services.** Use none of RDS, DocumentDB, EFS, a load balancer, a
  NAT gateway, CloudFront or extra EBS volumes. A snapshot also costs a little.
- **Watch outbound traffic.** Data out to the internet is billed past the free
  allowance. Demo traffic is tiny, but do not host large downloads here.
- **Before the credits end:** back up (above), pull the backup and the `.env`
  to your PC, then terminate the instance and release the Elastic IP.

## How it is put together

| File                     | What it does                                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `docker-compose.aws.yml` | The whole stack. Standalone, not an overlay, so that what runs is in one file (the file's header says why). |
| `compose.sh`             | `docker compose` with the right project directory and `.env`.                                               |
| `bootstrap.sh`           | Partial sparse clone, secrets, Mongo keyfile, folders, renewal timer, unattended upgrades.                  |
| `deploy.sh`              | Pull, data guard, checkpoint sha256, build, start, wait for health, certificate, smoke tests.               |
| `data-guard.sh`          | Refuses MIMIC-derived files and stray data.                                                                 |
| `cert.sh`                | Let's Encrypt HTTP-01 via nginx's port 80; self-signed fallback; the systemd timer runs `renew`.            |
| `backup.sh`              | `mongodump` plus the uploaded X-rays, to `~/backups`.                                                       |
| `copy-checkpoints.md`    | Which weights go where, with sizes and sha256.                                                              |

Memory caps (sum 6.8 GiB):

| Service     | Cap     | Notes                                                                |
| ----------- | ------- | -------------------------------------------------------------------- |
| `inference` | 4 GiB   | Both models: ~1.5 GiB RSS, ~2.0 GiB peak with a long discharge note. |
| `mongo`     | 1 GiB   | `--wiredTigerCacheSizeGB 0.25`                                       |
| `api`       | 768 MiB | `--max-old-space-size=512`                                           |
| `minio`     | 512 MiB |                                                                      |
| `redis`     | 256 MiB | `--maxmemory 200mb`                                                  |
| `web`       | 128 MiB |                                                                      |
| `nginx`     | 128 MiB |                                                                      |

Hardening:

- **API.** `NODE_ENV=production` and no stack traces in responses (5xx
  messages are generic). Cookies are `Secure`, `HttpOnly` and `SameSite=Lax`.
  CORS is off: the web app and the API share one origin.
- **Login limits.** nginx allows 5 login requests a minute per IP. The API
  also allows 10 failed logins per IP per 15 minutes.
- **Inference.** The service is reachable only on the internal network, and
  every call is HMAC-signed. The API refuses to start without the secret.
- **Containers.** They run with `no-new-privileges`. API and inference root
  filesystems are read-only.
